SECTION 1 — CRITICAL BUGS & BROKEN FUNCTIONALITY
================================================================

[CRITICAL] Courses page shows zero courses — data never loads
Page: courses.html
Problem: The entire course catalog renders "No courses found" on
first load. The heading says "Showing 24 courses" but the grid is
completely empty. This is the primary revenue page and it is
non-functional. Likely caused by JavaScript loading courses from
a mock data source that doesn't initialize, or a filter state bug
that fires before data populates.
Fix: Ensure course data is injected into the DOM before filters
run. Confirm the data array is populated and renderCourses() is
called on DOMContentLoaded. Add a visible loading state.

----------------------------------------------------------------

[CRITICAL] Free Library shows no resources — same blank-state bug
Page: library.html
Problem: The Library page is also completely empty on load.
"No resources found" is shown immediately despite 150+ resources
advertised on the homepage. This kills the free-tier value
proposition entirely.
Fix: Same root cause as courses.html. Apply the same fix.
Pre-populate featured resources in static HTML as a fallback.

----------------------------------------------------------------

[CRITICAL] OTP auth is cosmetic — no real backend, fake popup
Page: login.html / signup.html
Problem: The login advertises "Email OTP" and signup advertises
"Phone OTP" verification. The page itself notes "OTP will appear
as a popup card on screen" — meaning the code is displayed
on-screen to the user client-side, not sent via email/SMS.
Anyone can sign in without real verification.
Fix: Integrate Supabase Auth, Firebase Auth, or Clerk. Never
generate or display OTP codes client-side. All auth logic must
live server-side.

source. Ensure IDs are consistent between homepage and data array.

SECTION 3 — SECURITY VULNERABILITIES
================================================================

[CRITICAL] Client-side OTP generation — auth is bypassable
Page: login.html, signup.html
Problem: OTP is displayed client-side. Anyone can open DevTools,
find the OTP in JavaScript state, and authenticate as anyone.
Every account can be compromised by any visitor with DevTools.
Fix: Migrate to Supabase Auth or Firebase Auth immediately.
OTPs must be generated server-side, sent via SMS/email, and
verified server-side. Never trust the client for auth.

----------------------------------------------------------------

[CRITICAL] No CSRF protection on any form
Page: All forms
Problem: None of the forms include CSRF tokens. Once real auth
is added, all state-changing forms must include CSRF protection.
Fix: Use SameSite=Strict cookie attributes and/or synchronizer
token pattern. Supabase Auth handles this for auth endpoints.

----------------------------------------------------------------

[CRITICAL] No Content Security Policy (CSP) headers
Page: Global
Problem: No CSP header means injected scripts via XSS can execute
freely. Ironically the site hosts an "OWASP Top 10 Security"
resource without implementing basic security headers.
Fix: Add Content-Security-Policy header via Vercel's vercel.json
headers config. Whitelist only origins you actually use.

----------------------------------------------------------------

[IMPORTANT] Dashboard pages accessible without authentication
Page: teach.html, dashboard.html
Problem: Instructor dashboard is publicly accessible. Any visitor
can view earnings data, student lists, and course management
without any login.
Fix: Implement auth guards on page load that redirect
unauthenticated users to /login.html.

----------------------------------------------------------------

[IMPORTANT] No real rate limiting on OTP / login attempts
Page: login.html, signup.html
Problem: The "Attempt 0/5" OTP counter resets on page refresh —
it's entirely client-side. No real rate limiting exists.
Fix: Implement server-side rate limiting per IP and per account
on auth endpoints. Show lockout timers from server-returned data.

----------------------------------------------------------------

[IMPORTANT] No HSTS headers
Page: Global
Problem: No Strict-Transport-Security header to prevent protocol
downgrade attacks.
Fix: Add "Strict-Transport-Security: max-age=31536000;
includeSubDomains" via vercel.json headers.

----------------------------------------------------------------

[IMPORTANT] No real payment integration
Page: course-detail.html, pricing.html
Problem: "Enroll Now" and "Upgrade to Pro" link to signup page
without any payment handling. No transaction occurs.
Fix: Integrate Razorpay (primary, for Indian market) and Stripe
(secondary, for international). Wire up before any real sales.

----------------------------------------------------------------

[NICE TO HAVE] No X-Frame-Options / clickjacking protection
Page: Global
Problem: Without X-Frame-Options: DENY, the site can be embedded
in an iframe for clickjacking attacks on login/payment pages.
Fix: Add "X-Frame-Options: DENY" or "Content-Security-Policy:
frame-ancestors 'none'" via vercel.json.

SECTION 4 — SEO DEFICIENCIES
================================================================

[CRITICAL] Course catalog is JS-rendered — invisible to Google
Page: courses.html, library.html
Problem: Since courses only render via JavaScript (and currently
fail to render at all), Google's crawler sees an empty page.
All 200+ courses and 150+ resources are completely unindexable.
No organic traffic for queries like "Next.js course India."
Fix: Server-side render (SSR) the course catalog, or use static
generation (SSG) with pre-built HTML per course. Consider
migrating to Next.js for proper SSR.

----------------------------------------------------------------

[CRITICAL] No Open Graph / Twitter Card meta tags on any page
Page: All pages
Problem: No og:title, og:description, og:image, or Twitter Card
tags. Sharing any BrainByte link shows a blank, unbranded preview
on LinkedIn, Twitter, or WhatsApp.
Fix: Add OG tags to every page. For course detail pages, populate
og:title and og:image dynamically with course data. Create a
default site OG image (1200x630px) for generic pages.

----------------------------------------------------------------

[IMPORTANT] No sitemap.xml or robots.txt
Page: Root
Problem: No sitemap to help search engines discover pages.
No robots.txt to guide crawlers.
Fix: Generate sitemap.xml listing all static and course detail
URLs. Add robots.txt allowing public pages and blocking admin
routes. Submit sitemap to Google Search Console.

----------------------------------------------------------------

[IMPORTANT] No structured data (JSON-LD) for courses
Page: course-detail.html
Problem: Google supports Course schema that shows ratings, price,
and instructor in search results. Competitors like Udemy use this
heavily. BrainByte has none.
Fix: Add JSON-LD structured data to each course detail page with:
name, description, provider, url, offers (price), aggregateRating.

----------------------------------------------------------------

[IMPORTANT] Course detail page has generic meta description
Page: course-detail.html
Problem: Meta description is identical for every course. Dynamic
meta tags must be populated per course from query params.

----------------------------------------------------------------

[IMPORTANT] Missing canonical tags
Page: All pages
Problem: Course pages use query string parameters. Without
canonical tags, Google may index multiple URL variants of the
same page — duplicate content issue.
Fix: Add <link rel="canonical"> to each page. For course detail
pages, canonicalize to a clean slug-based URL like
/courses/nextjs-supabase-blueprint.

----------------------------------------------------------------

[NICE TO HAVE] Page titles not updated for category filter states
Page: courses.html with filters
Problem: Filtering by "Web Development" doesn't update the page
title to "Web Development Courses — BrainByte." Unique titles
per category would improve Google rankings for category searches.

SECTION 5 — PERFORMANCE PROBLEMS
================================================================

[IMPORTANT] Course thumbnails have no lazy loading or dimensions
Page: index.html, course-detail.html
Problem: Thumbnail images lack width/height attributes or
loading="lazy". Causes Cumulative Layout Shift (CLS) and loads
all images regardless of visibility.
Fix: Add loading="lazy", width, height, and decoding="async" to
all non-hero images. Serve images in WebP format.

----------------------------------------------------------------

[IMPORTANT] No font display swap
Page: Global
Problem: Without font-display: swap, users on slow connections
see invisible text while fonts load. Affects LCP and CLS scores.
Fix: Add &display=swap to Google Fonts URL. Or self-host fonts
with font-display: swap.

----------------------------------------------------------------

[IMPORTANT] External video loads unconditionally on page load
Page: resource-detail.html
Problem: Video player loads a full MP4 from external CDN without
a poster image or progressive loading. Consumes mobile data.
Fix: Add a poster attribute with a thumbnail. Lazy-initialize the
player only on user interaction. Host videos on Cloudflare Stream
or Mux for adaptive bitrate streaming.

----------------------------------------------------------------

[NICE TO HAVE] No PWA / offline capability
Page: Global
Problem: Many Indian users are on mobile with inconsistent
connectivity. Offline access to PDFs and course progress syncing
would be a strong differentiator.
